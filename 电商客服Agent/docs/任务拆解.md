# 电商客服Agent 任务拆解（PRD格式）

> 本文件是执行清单，照着做，做完一项划一项。

---

## 一、背景目标

**做什么**：用一个 AI 客服 Agent，在飞书/WhatsApp/抖音/淘宝 上回答客户问题。

**核心价值**：客户问问题，AI 自动回答，不用人工一一回复。

**成功标准**：客户发消息，AI 能理解意图、查知识库、发出回答，全程自动。

---

## 二、核心流程

```
客户消息（飞书/WhatsApp/抖音/淘宝）
    ↓
[意图识别] → 判断是什么类型的问题
    ↓
[查知识库] → 查商品/FAQ/政策
    ↓
[组装回答] → 把查到的信息组织成自然语言
    ↓
[发回客户] → 通过原平台发回给客户
```

---

## 三、任务清单

  - `商品库`：商品ID、名称、价格、规格、库存
  - `FAQ`：常见问题、标准回答
  - `政策库`：退换货规则、优惠券规则、发货时间

  - 用 `lark-im` 发消息回客户

- [ ] **调 Claude API**
  - 把客户消息发给 Claude
  - 让 Claude 理解意图、查知识库、组装回答

- [ ] **全流程跑通**
  - 收到真实消息 → AI 处理 → 发回回答
  - 不是 demo，是真实可用的

---

### P1（按需加，上线后慢慢加）

- [ ] **入口 Hook**
  - 事件：`UserPromptSubmit`
  - 功能：识别高风险词（退款/取消/投诉/查地址）
  - 效果：高风险 → 标记 → 走人工

- [ ] **出口 Hook**
  - 事件：`PostToolUse`
  - 功能：检查回答是否包含未验证的价格/手机号/身份证
  - 效果：敏感信息 → 脱敏或阻断

- [ ] **监督 Agent**
  - 功能：AI 回答后，再过一个"审核 Agent"判断是否合格
  - 效果：不合格 → 重写或转人工

---

### P2（后期做，不影响上线）

## 四、知识库设计

### 4.1 商品库（飞书多维表格）

| 字段 | 类型 | 说明 |
|------|------|------|
| 商品ID | 文本 | 唯一标识 |
| 商品名称 | 文本 | 客户会问的名字 |
| 价格 | 数字 | 单位：元 |
| 规格 | 文本 | 如：S/M/L、红色/蓝色 |
| 库存状态 | 文本 | 有货/缺货/预售 |

### 4.2 FAQ（常见问答）

| 字段 | 类型 | 说明 |
|------|------|------|
| 问题关键词 | 文本 | 客户可能怎么问 |
| 标准回答 | 文本 | AI 应该如何回答 |
| 适用平台 | 文本 | 飞书/WhatsApp/抖音/淘宝 |

### 4.3 政策库

| 字段 | 类型 | 说明 |
|------|------|------|
| 政策类型 | 文本 | 退换货/优惠券/发货/其他 |
| 规则内容 | 文本 | 具体规则 |
| 有效期 | 文本 | 什么时候过期 |

## 五、Hooks 设计（按需）

### 5.1 入口 Hook（UserPromptSubmit）

**什么时候触发**：客户发消息，AI 处理之前

**做什么**：
```bash
# 检查消息是否包含高风险词
if echo "$message" | grep -E "退款|取消订单|投诉|查.*地址|注销" > /dev/null; then
    # 写状态文件，标记高风险
    echo "high_risk=true" >> /tmp/customer_status.json
fi
```

### 5.2 出口 Hook（PostToolUse）

**什么时候触发**：AI 回答，准备发出之前

**做什么**：
```bash
# 检查回答是否包含敏感信息
if echo "$answer" | grep -E "[0-9]{11,}|身份证|完整银行卡" > /dev/null; then
    # 脱敏或阻断
    echo "[人工确认中]"
fi
```

## 六、反馈收集

### 6.1 显式反馈
- 消息末尾加"这个回答有帮助吗？👍 有帮助 👎 没帮助"
- 客户点 👍 → 记录 good case
- 客户点 👎 → 记录 bad case + 原因

### 6.2 隐式反馈
- 客户追问同一个问题 → 上条回答质量差，记录 bad case
- 客户转人工 → Bot 搞不定，记录 bad case
- 30分钟内无追问 → 大概率满意，不用记录

### 6.3 Bad Case 使用
- 每周拉取一次 bad_cases.jsonl
- 分析高频问题
- 更新提示词，减少同类问题
- 高质量问题加入 Few-shot 示例
