# 电商客服 Agent 知识对照表

> 这个项目需要哪些知识？和仓库里哪些章节对应？

## 总体映射

| 项目模块 | 需要解决的问题 | 对应仓库章节 | 学完能解决什么 |
|---------|--------------|------------|--------------|
| **收消息** | 不同平台（飞书/WhatsApp/抖音/淘宝）怎么收消息 | `05-MCP/` | 用 MCP 接入飞书；其他平台查官方 API |
| **发消息** | 怎么把回答发回给客户 | `05-MCP/` | 同上 |
| **知识库查询** | 客户问产品/价格/参数，怎么查 | `05-MCP/`（`lark-base`）| 飞书多维表格做知识库 |
| **客服 Agent** | 怎么让 AI 理解意图、查库、组装回答 | `04-subagents/`, `03-skills/` | 编排多步流程 |
| **入口 Hook** | 怎么在 AI 处理前拦截并识别高风险意图 | `06-hooks/` | 用 `UserPromptSubmit` 强制做意图校验 |
| **出口 Hook** | 怎么在发出前检查敏感信息 | `06-hooks/` | 用 `PostToolUse` 做脱敏 |
| **监督 Agent** | 怎么让另一个 AI 审核回答质量 | `04-subagents/` | 多个 Agent 协作 |
| **反馈日志** | 怎么自动收集 Good/Bad cases | `02-memory/` | 把日志存成结构化数据 |
| **持续记忆** | 怎么让 Agent 记住之前的对话上下文 | `02-memory/` | CLAUDE.md / memory 文件跨 session 记忆 |
| **多平台切换** | 换平台时怎么最小改动 | `05-MCP/` | 抽象接口，平台 API 当实现细节 |

---

## 逐章对应

### 01-slash-commands
**用到的地方**：不多，主要了解 Claude Code 的基本交互方式。

**不需要重点学**：知道 `/` 可以调命令就行。

---

### 02-memory
**用到的地方**：
- `src/customer_agent.py`：写对话日志到 `.jsonl`，后续分析
- 反馈闭环：Bad Case 越来越多，怎么用 memory 文件组织

**重点**：
- `memory/` 目录下 `.md` 文件的格式
- CLAUDE.md 是项目级记忆，客服 Agent 可以读它了解业务规则

**实践中**：客服 Agent 的 system prompt 可以从 `知识库/design.md` 读取，不需要每次塞进 context。

---

### 03-skills
**用到的地方**：
- 整个项目的起点：怎么用 `lark-im` 收消息、用 `lark-base` 查知识库
- 自己封装技能：比如把"查商品"封装成一个 skill

**重点**：
- skill 是 `.claude/skills/` 下的 `.md` 文件
- 可以参考现有的 `lark-im` / `lark-base` 写自己平台的 skill

---

### 04-subagents
**用到的地方**：
- **客服 Agent**：主流程，负责理解 + 查库 + 组装回答
- **监督 Agent**：审核客服的回答是否合格

**重点**：
- 一个 Agent 调用另一个 Agent（`SendMessage`）
- Agent 之间怎么传信息（通过工具调用结果，而不是直接调）

**实践中**：
```python
# 客服 Agent 回答完了 → 触发监督 Agent 审核
supervisor_result = supervisor_agent.run(question, answer)
if not supervisor_result["passed"]:
    # 标记需要人工，或让 AI 重写
```

---

### 05-MCP
**用到的地方**：
- 飞书消息收发：`lark-im`
- 飞书知识库查询：`lark-base`
- 其他平台：WhatsApp Business API / 抖音 open API / 淘宝开放平台

**重点**：
- MCP 工具怎么调（在代码里用 `mcp__lark__im_send_message`）
- MCP server 怎么配（在 `settings.json` 里）

**实践中**：
- 先用飞书跑通，因为有现成 MCP
- 换平台时，只换 MCP 工具层，核心逻辑不变

---

### 06-hooks
**用到的地方**：
- **入口 Hook**：`UserPromptSubmit` — 识别高风险意图（退款/投诉/查地址）
- **出口 Hook**：`PostToolUse` — 发送前脱敏检查

**重点**：
- `PreToolUse` / `PostToolUse` 的阻断逻辑（`exit 2`）
- `UserPromptSubmit` 怎么从 stdin JSON 取 `user_prompt`
- Hook 是**强制执行**，不是"建议"

**实践中**：
```bash
# hooks/intent_check.sh
# 匹配 "退款|取消订单|投诉" → 写高风险标记文件
```

---

### 07-plugins
**用到的地方**：
- 如果要把客服 Agent 打包成插件发布
- 或者参考 `devops-automation` 插件的结构

**不太需要重点学**：项目阶段一、二先不涉及插件。

---

### 08-checkpoints
**用到的地方**：
- 客服 Agent 出错了，怎么回退到之前的状态
- 比如：AI 发了错误的价格，需要回退重发

**不太紧急**：阶段一、二先不做，阶段四再考虑。

---

### 09-advanced-features
**用到的地方**：
- 了解 Claude Code 的高级能力（大概率用不上这个项目）

---

### 10-cli
**用到的地方**：
- 调试：怎么用 `claude` 命令跑测试
- 部署：怎么把脚本部署到服务器

**了解即可**：能用 `claude` 跑脚本、能看懂 CLI 文档就行。

---

## 学习优先级建议

### 现在立刻可以开始写代码的组合

| 组合 | 能做 | 对应章节 |
|------|------|---------|
| `04-subagents` + `05-MCP` | 客服 Agent 主流程 | 跑通：收消息→理解→查库→组装回答→发消息 |
| `06-hooks` | 入口/出口 Hook | 在主流程上加意图识别 + 脱敏检查 |
| `02-memory` | 日志 + 反馈收集 | 把对话记录到 JSONL，积累 Bad Case |

**结论**：学完 06 就可以开始阶段一二的代码了，04/05 是实现层，02 是数据层。
