# 电商客服 Agent

> 用 Claude Code 全套技术栈，从零搭一个可落地的电商客服 Agent。

## 项目定位

**实践项目**，不是教程。用来把 `claude-howto-zh-cn` 学到的知识真正用起来。

目标：跑通跨平台（飞书/WhatsApp/抖音/淘宝）客服的核心流程，平台 API 是小事，**怎么让 AI 回答得准、回答得稳**才是核心。

## 架构概览

```
客户消息（飞书/WhatsApp/抖音/淘宝）
    ↓
[入口 Hook] → 意图识别 + 高风险标记
    ↓
客服 Agent（Claude API）
    ↓ 查询知识库
[执行 Hook] → 参数校验 + 脱敏
    ↓
监督 Agent（Claude API）→ 质量审核
    ↓ 通过/不通过
[出口 Hook] → 发送前最终检查
    ↓
发出回复
    ↓
[反馈收集] → good/bad cases → 日志
```

## 核心认识

> **Hooks 是守门员，不是进攻球员。**
> 它管"不能做什么"，不管"怎么做得好"。

> **Bad Case 积累是让 AI 越来越准的唯一方式。**
> 靠提示词调优是手动补丁，靠反馈闭环是自动进化。

## 什么时候加 Hooks

| 阶段 | Hook 类型 | 触发条件 |
|------|----------|---------|
| 流程跑通后 | 入口 Hook | 客户消息包含"退款/取消/投诉"等高风险词 |
| 流程跑通后 | 出口 Hook | AI 回答包含未验证的价格/手机号/身份证 |

## 知识库设计

### 要有哪些内容？

```
商品表：商品ID、商品名称、价格、规格、库存状态
FAQ表：常见问题、标准回答
政策表：退换货政策、优惠券规则、发货时间
```

### 怎么建？

用 `lark-base` skill，在飞书多维表格里建 3 张表：
- `商品库`——商品基础信息
- `FAQ`——常见问答
- `政策库`——退换货/优惠/发货政策
