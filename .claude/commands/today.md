# Today / 今日学习日报（自动归档版）

## 今天的工作痕迹（Claude Code 会先真的执行这些命令，把输出注入到 prompt）

- 📅 今天日期：!`date +%Y-%m-%d`
- 🌿 当前分支：!`git branch --show-current`
- 📌 今日提交列表：!`git log --since="1 day ago" --oneline`
- 📊 今日改过的文件统计：!`git log --since="1 day ago" --stat`
- 📝 未提交的改动：!`git status --short`
- ✏️ 未提交改动的具体内容摘要：!`git diff --stat`
- 💡 用户附加的主题 hint（可能为空）：`$ARGUMENTS`

---

## 你的任务

分两步做：**先生成日报内容**，**再保存到文件**。

---

### 第 1 步：生成日报内容

严格按下面这个格式生成，不要加多余段落：

```
# 📅 <今天日期> 学习日报

🌿 分支：<分支名>

---

## 🎯 今天主要学了这几件事

1. <主题一>
   → <一句话核心收获>

2. <主题二>
   → <一句话核心收获>

（有几个主题就列几个，2-5 个比较合适）

---

## 💡 关键收获（选 1-3 个最有价值的知识点，多写一点）

### <知识点标题一>
<2-3 句话讲清楚，可以带例子>

### <知识点标题二>
<...>

---

## ⚠️ 卡壳 & 待办

- <今天有没有哪里卡了没解决，或者踩了坑>
- <明天想继续追的问题>

（如果没有卡壳的地方，就写"今天挺顺 ✨"）

---

## 🌟 一句话自我肯定

<根据今天的进展，给一句轻松真诚的话，比如"从怕命令行到今天写出自己的第一个 slash command，进步很大 👏">
```

**生成时要求**：

- **用轻松的中文表达**，别搞成"XX 项目日结报告"那种官腔
- **重点讲今天新学到的**；如果 commit 里明显有"改配置""调格式"这类杂事，一笔带过就行
- 如果**今天的提交太少或者一条都没有**：不要硬凑，直接告诉用户"今天 git 上没啥动静，要不要说说你线下学了啥？"，等用户回复后再继续；用户回复的补充信息就是日报内容的主要素材
- "今天日期"用上面 `date +%Y-%m-%d` 读到的那个，不要自己编
- 用户传的 `$ARGUMENTS` 如果非空，把它当作**今日主题优先方向**参考（比如用户传了"练习 slash command"，日报就重点讲这方面）

---

### 第 2 步：自动归档到 `学习笔记/Z-日报/`

**这一步用 Write 工具执行**（不需要问用户"要不要保存"，直接保存）。

**文件命名规则**：

```
学习笔记/Z-日报/<日期>-<主题总结>.md
```

- **日期**：用上面 `date` 读到的 `YYYY-MM-DD` 格式
- **主题总结**：**你自己**根据今天日报的核心内容，总结出一个 **6-15 个字的中文短语**当作文件名后缀，能一眼看出这天在学什么。比如：
  - `2026-07-20-学会Slash-Command占位符.md`
  - `2026-07-21-初探Hooks事件驱动.md`
  - `2026-07-22-MCP接入本地数据库.md`
- **主题里不要出现斜杠、冒号、问号等 Windows 文件名非法字符**，用连字符或去掉

**写入内容**：就是第 1 步生成的完整日报（从 `# 📅` 开始那一整段）。

保存完，给用户一个简短确认：

```
✅ 日报已归档：学习笔记/Z-日报/<刚才那个文件名>.md
```

---

## 注意事项

- **只读 git，不改 git**：不要 add、commit、push 任何东西
- **除了那个日报 md 文件之外，不要动任何其他文件**
- 如果 `学习笔记/Z-日报/` 目录不存在，用 Bash `mkdir -p 学习笔记/Z-日报` 建一下再写
- 如果**同一天已经有日报文件**了（同名或同日期前缀），在文件名末尾加 `-2`、`-3` 之类的序号避免覆盖

>
