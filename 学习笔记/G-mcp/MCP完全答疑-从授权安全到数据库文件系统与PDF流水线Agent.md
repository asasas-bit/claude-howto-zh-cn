## 1. 安装授权能不能"让干啥就干啥"？🟡

**一句话结论：流程上可以照做，但每次授权前花 10 秒看一眼"我在给谁、什么权限"——就这一个动作，不能省。**

你的理解对的部分：正规 MCP 的安装确实就是这个套路——复制一段配置/提示词 → 客户端自动安装 → 弹窗或扫码授权 → 连上。GitHub、生财有术你都是这么成的，以后也大多是这样。

**类比**：这跟手机装 App 一模一样。装 App 时你也是"点下一步、点同意"，但如果一个**手电筒 App 要求读你的通讯录和短信**，你会停下来对吧？MCP 授权就是那个权限弹窗。

**为什么不能 100% 无脑**：MCP server 是别人写的程序，它拿着你的授权，理论上能看到你账号能看到的一切。所以：

- ✅ **看来源**：GitHub 官方、Neon 官方、飞书官方、模型上下文协议官方目录里的——放心装。不知名小网址、群里陌生人发的配置——停一下，先搜一下这个 MCP 有没有官网/GitHub 仓库。
- ✅ **看权限范围**：授权页面经常能选范围。GitHub 授权时能选"所有仓库"还是"只选几个仓库"——能选小就别选大；数据库能给只读就别给读写。
- ✅ **一个危险信号**：任何让你**把密钥复制粘贴进对话框、网页、或者发给"客服"** 的，都是骗局。正规流程里密钥只填进客户端自己的配置窗口。

你说的"它让我扫码我就扫"——OAuth 扫码（跳转到官方网站登录授权）本身是安全机制，比复制 key 还安全。**口诀：装软件看来源，给权限看范围，要密钥的弹窗一律警惕。**

## 2. 数据库 MCP 是干嘛的？❌

**一句话结论：数据库是网站/小程序背后存数据的"超级 Excel 仓库"；数据库 MCP 就是给 AI 一张访客证，让它能直接进去帮你查数、建表、整理数据，你用中文说话就行。**

**先补数据库本身**（你说一直见过但没用过）：

- 网站的用户、订单、文章，小程序的收藏、评论，最终都存在**数据库**里。你说的 PostgreSQL（读 "Post-gres"，不是 Post-gray 😄）是最流行的免费数据库之一，同类还有 MySQL、SQLite。
- 里面的数据按**表**存：一张"用户表"，一行一个用户，一列一个字段（姓名、注册时间……）。跟 Excel 很像，区别是它能装几百万行、多人同时用、程序能自动读写。
- 跟数据库说话用一种叫 **SQL** 的语言。你不用学，但认识四个词的"危险等级"很有用：

| SQL 词 | 干什么 | 危险度 |
|---|---|---|
| SELECT | 查数据 | 安全，怎么查都不坏 |
| INSERT | 加数据 | 低 |
| UPDATE | 改数据 | ⚠️ 高（改错了一片数据就变了）|
| DELETE | 删数据 | ⚠️ 最高（删了找不回来）|

**数据库 MCP 改变了什么**：以前你想知道"上个月新增多少用户"，得让程序员写 SQL；装了数据库 MCP，你直接用中文问，Claude 自己翻译成 SQL、去查、把结果讲给你听。你说"帮我建张表存我的客户资料，字段有姓名、微信、来源、跟进状态"，它就直接建好了。

**类比**：数据库是上锁的档案室，以前你得托专人（写代码的人）进去翻；MCP 给 AI 办了张访客证，它自己进去翻，还能按规矩登记。

**你现在就有个活例子**：咱们这个对话里就接了一个 **Neon MCP**（Neon 是云上的 PostgreSQL 服务，注册就有免费数据库）。我手上现在有 60 多个数据库工具——建库、建表、查数据都能干。你要是想练手，最省事的路径就是：注册 Neon 免费账号 → 复制它官方给的 MCP 配置 → 直接对话"帮我建个库存表，我报数据你录"。

**边界和坑（重要）**：数据库 MCP 一般同时给"查"和"改/删"的能力。规矩两条：

1. **练手**：用 Neon 免费库，随便折腾，删了也不心疼。
2. **真网站在用的库（生产库）**：要么给只读权限，要么连它的"分支/备份"（Neon 这种支持开分支，像 Git 一样）。因为 UPDATE/DELETE 是不可逆的——正规 MCP 在执行删改前都会弹确认问你，**那个弹窗别无脑回车**。

## 3. 文件系统 / GUI / 浏览器类 MCP 的作用 ❌

**一句话结论：这一类 MCP 是给 AI 配"手和眼"——操作文件、点浏览器、看屏幕。但有个你这个阶段最容易搞混的点：在 Claude Code 里，文件操作它天生就会，不需要装文件系统 MCP。**

逐个说：

| MCP | 作用 | 你什么时候用得上 |
|---|---|---|
| **filesystem（文件系统）** | 让 AI 读写**你指定的某个文件夹**里的文件 | 主要给 Claude Desktop、ChatGPT 桌面版这类"碰不到你硬盘"的聊天软件用。Claude Code / Codex 自带终端，本来就能操作文件，**不用装它** |
| **Playwright** | 让 AI 操作浏览器：打开网址、点按钮、填表单、截图、抓数据 | 批量网页操作、自动填表、网页自动化测试 |
| **Chrome DevTools** | Chrome 浏览器的"开发者工具箱"：看控制台报错、看网络请求、查性能 | 做网页/网站时让 AI 自己看着报错修 bug（你装过，这个是对的）|
| **GUI 类**（你说的"giu"） | 看屏幕截图、点桌面软件的按钮 | 操作没有 API 的老软件、自动化桌面流程 |
| **context7**（你用过） | 查编程库的**最新官方文档**——纠正一下，它查的不是学术文献，是软件说明书（比如某个 Python 包最新版怎么用），防止 AI 凭旧记忆瞎编 | 写代码相关时很有用 |

**类比**：Claude Code 像住你家的保姆，本来就有家门钥匙（能读写文件、能跑命令）；Claude Desktop 像来上门咨询的顾问，文件系统 MCP 是你临时给它开的**一间屋子**的门——配置时指定哪个文件夹，它就只能进那间，出不去。这个"只开一间屋"的设计本身就是安全机制。

浏览器类 MCP 还有个隐藏价值：**AI 能"看见"网页了**。它点开页面、截图、读内容，然后自己判断下一步点哪——这就是为什么有人能让 AI 自动跑完一整个网页流程。

## 4. 多个 MCP 是不是都塞进一个配置文件？✅

**对，你理解得完全正确。**

配置就是一个 JSON 文件，里面有个 `mcpServers`（MCP 服务器列表），每个 MCP 占一段，想加几个加几个：

```json
{
  "mcpServers": {
    "github": { ...一段... },
    "neon":   { ...一段... },
    "mineru": { ...一段... }
  }
}
```

**类比**：这就是个**电话簿**。每个 MCP 是一个联系人，登记一条就能打电话，登记十条就能打十个。

三个小提醒（边界）：

1. **各客户端的电话簿是分开的**。你在 Codex 里装的 MCP，Claude Code 里没有，反过来也是——谁用就在谁那里登记一次。
2. **配置可以跟项目走**。Claude Code 里项目根目录的 `.mcp.json` 会跟着项目文件夹走，团队共享项目时别人也能直接用——但**密钥不能写进去**（会被提交到 Git），密钥走环境变量或用户级配置。
3. **不是越多越好**。装太多 MCP，AI 每次要从一大堆工具里挑，会变慢、偶尔挑错。用不上的别装。

## 5. 自己写 API 程序 vs 包成 MCP vs 官方现成 MCP；key 和 token 🟡

这是你问得最好的一个问题，讲透。

**一句话结论：API 是餐厅的取餐窗口，MCP 是给 AI 配的一个"代取餐专员"；不管走哪条路，进门刷的都是同一把钥匙（API key）——MCP 没有发明新账号体系。**

三层关系：

| 方案 | 是什么 | 优点 | 缺点 |
|---|---|---|---|
| **你写程序调 API**（MinerU API + 你的代码）| 你自己雇了个跑腿，把"上传 PDF→等结果→下载 MD→校准"每一步写死 | 流程固定、批量跑又快又稳、不花 AI 对话钱 | 改流程要改代码；只有你能用；步骤全得自己想 |
| **用官方/现成 MCP** | 别人把同一个 API 包成了 MCP，等于配了个驻场办事员，AI 直接跟它对话 | 零代码；AI 灵活安排步骤；能和别的工具串起来 | 每步都过模型，费对话 token；特别大批量不如写死程序稳 |
| **自己把程序包成 MCP** | 给你的跑腿套一身 MCP 标准制服 | 能在所有支持 MCP 的客户端里复用、能分享 | 有开发成本；**只给你自己一个项目用的话不值得** |

**关键判断**：你自己那套程序要不要包成 MCP？——**大概率不用**。包 MCP 的价值是"让没有手的客户端（Claude Desktop 这类）也能用"。你在 Claude Code/Codex 里，AI 本来就能直接跑你的脚本，你把流程写进 CLAUDE.md 或做成 skill，效果一样，还省事。**记住这个仓库的主线分工：MCP 负责"接外部能力"，skill/CLAUDE.md 负责"定流程"。**

**key 和 token 是一回事吗？** 是同一类东西，两种发法：

- **API key / token**：你在服务商后台复制一串密钥，填进 MCP 配置的 `env`（环境变量）里。你 MinerU API 用的那把 key，MCP 里直接复用，不用重新买。
- **OAuth 授权**（GitHub、生财有术那种扫码/弹窗登录）：你不用碰密钥，扫码登录后客户端自动保管 token。更省心，过期了它会让你重新扫一次。

**类比**：MCP 是给顾问装了部电话，但打给银行还是要刷你的银行卡密码（API key）；OAuth 是你亲自去银行签了授权书，以后顾问凭签字记录办事，你不用把密码给任何人。

⚠️ 顺带纠正一个安全细节：key 只填在客户端的配置里，**别贴进对话框、别提交到 Git**。对话记录可能被同步，Git 仓库可能被别人看到。

## 6. MCP 要学什么？注意事项？🟡

**一句话结论：MCP 本身没什么可"学"的，你的用法（需要时找一个、装上、授权、用）就是正道。要掌握的是四个故障/安全检查点。**

你说的网络、代理、token、权限，方向全对。我把它变成你能用的排查清单。MCP server 有三种跑法，失败原因各不相同：

| 跑法 | 长什么样 | 常见失败原因 |
|---|---|---|
| **本地启动** | 配置里写 `npx xxx` 或 `uvx xxx` | 电脑没装 Node.js（npx）或 Python/uv（uvx）；首次下载包慢，国内网络可能要代理/镜像 |
| **远程网址** | 配置里写 `https://xxx`（生财有术、Neon 远程这类）| 网络访问不到那个网址（公司防火墙、代理没开）|
| **连本地软件** | 比如连本地数据库 | 软件没开、端口不对 |

**症状对照**：装完之后工具不出现 / 一调用就超时 → 八成是网络或运行时没装；授权弹窗报错 → 回调地址/网络问题；工具在但调用 401/403 → key 过期或没填对。

**四件事记住就够**：

1. **来源可信**（第 1 题讲过）
2. **权限最小**：只读够用不给写，能选单个仓库不给全账号
3. **钥匙收好**：key 在配置/env 里，不进对话、不进 Git
4. **调用确认弹窗看一眼**：Claude Code 里 MCP 每次动手（尤其写、删、发出去）前会弹确认，扫一眼它"要对什么做什么"再放行

**怎么学**：不用专门学。**带着真任务装一个**——你不是正好要做 PDF 流水线吗？就装 MinerU MCP，装的时候读一眼配置那几行（`command` 是启动命令、`env` 里放 key），装完直接问 Claude："这个 MCP 给了我哪些工具？"用一次，全懂了。这个仓库的 `05-mcp/` 目录里也有中文教程，卡住了可以翻。

## 7. 你的"PDF→MD→文案 Agent"想法 ✅

**一句话结论：完全成立，而且这就是 MCP 的标准正确用法。但有个概念要摆正：在 Claude Code 里这"不叫装个 MCP"，这叫搭一个项目工作流——MCP 只是手，流程手册在 CLAUDE.md / skill 里。**

你设想的链路：

```
PDF 原件 → MinerU MCP 解析成 MD → 大模型校准 → 读你的参考文案学风格 → 输出文案/话术
```

这条链每一环都成立。对比你以前的做法：

- **以前**：写程序把每一步写死。优点是批量稳；缺点是"校准、按风格写文案"这种需要判断的活，程序写不了，还得人肉来。
- **现在**：**机械活用 MCP，判断活用模型，流程规矩写进 CLAUDE.md**。MinerU MCP 干解析（手），Claude 干校准和写作（脑），CLAUDE.md 告诉它"按什么标准校准、我的文风是什么、标签怎么打"（操作手册）。

**具体落地长这样**（你下次可以直接试）：

```
pdf-to-copy/
├── input/        ← 扔 PDF 原件
├── output-md/    ← 解析出的 MD
├── 参考文案/      ← 放你的旧文章、话术样本
└── CLAUDE.md     ← 写流程规矩
```

CLAUDE.md 里用大白话写："先用 MinerU 工具把 input/ 里的 PDF 转成 MD 存到 output-md/；转完按这份校准清单检查（标题层级、表格、乱码）；然后读 参考文案/ 里的文风，每篇资料产出 3 条小红书文案。"——然后你把 PDF 一扔，说"开工"，它就跑完了。跑顺了以后，这套流程可以做成一个 **skill**，以后任何项目里一句话调用。

**两笔账分开算**（你问的 token）：

- MinerU MCP 要 **MinerU 的 API key**——就是你以前 API 用的那把，填进 MCP 配置，不用重新申请。
- 校准、写文案费的是 **Claude/Codex 的对话 token**。
- MinerU 解析本身按 MinerU 的计费走（跟你以前调 API 一样）。

**两个边界提醒**：

1. **批量上千个 PDF 的纯解析**，你原来的脚本其实更省钱更稳——聪明的做法是**混合**：脚本批量跑解析，MCP/Agent 负责后面的校准和写作。不用非此即彼。
2. MinerU 官方有没有维护 MCP、叫什么名字，**这个我不确定**（MinerU 是 OpenDataLab 的开源 PDF 解析工具，社区有人做过 MCP server，但是否官方维护我不能打包票）。你以 MinerU 官方文档/GitHub 搜到的为准，装的时候套用第 1 题的"看来源"原则。

## 🧩 补充：你没问但容易踩的 3 个点

1. **项目级配置 vs 用户级配置**。放在项目文件夹里的 `.mcp.json` 可以提交 Git、跟团队共享（但 key 用环境变量，别写进去）；放在你用户目录的配置是你所有项目通用的。给团队共享 → 项目级；你自己的私货（比如生财有术）→ 用户级。
2. **本地 MCP 需要"运行时"**。配置里写 `npx` 的要先装 Node.js，写 `uvx` 的要先装 uv/Python。"装完工具不出现"第一反应查这俩，而不是怀疑 MCP 本身。
3. **MCP 工具和 Claude Code 自带能力会重复**。文件操作、跑命令、Git 这些 Claude Code 天生就会，别看到个 filesystem/git MCP 就装——重复的工具只会让选择变乱。MCP 用来接它**本来够不着**的东西：数据库、浏览器、飞书、MinerU 这种外部服务。

## 🪢 串成一条线

MCP 就是**给 AI 接外设的标准插座**：数据库 MCP 让它够得着你的数据，浏览器 MCP 给它手眼，MinerU MCP 给它 PDF 解析能力，GitHub MCP 给它仓库权限。API 本来就存在，MCP 只是把"取餐窗口"接到了 AI 手上，进门刷的还是同一把钥匙。你不需要学插座怎么造——会三件事就够：**从可信来源拿插座、插之前看它要什么电（权限）、钥匙自己收好**。而你的 PDF 流水线想法之所以对，是因为你无意中摸到了正确分工：**MCP 当手，CLAUDE.md/skill 当操作手册，模型当大脑**——机械活交工具，判断活交模型，流程规矩写下来。

**心智模型一句话**：*MCP 是 AI 的"外设驱动"，装上就多一项能力；授权像装 App，看来源、看权限；key 是家门钥匙，只给正规门锁，不给路人。*
