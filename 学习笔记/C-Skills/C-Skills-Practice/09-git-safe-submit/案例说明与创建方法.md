# 案例 09：安全本地提交

## 1. 原始表达特征

这个案例来自现有 `01-slash-commands/commit.md` 以及后续讨论：

- 分析当前 Git 状态和 diff；
- 用户可以传入提交信息，也可以让 AI 生成；
- 创建一次本地 commit；
- 保留 `Bash(git ...)`；
- 不自动 push；
- 高风险操作只允许用户手动调用。

## 2. 结构化后的任务定义

> 在用户明确调用后，检查当前分支、状态、diff 和最近提交，识别敏感信息与不相关改动，只暂存本次相关文件，生成或使用用户提供的 Conventional Commit 信息，创建一次本地 commit，并验证结果；禁止 push。

## 3. 为什么是简单 Skill

它虽然会产生真实 Git 修改，但流程集中、命令固定，不需要模板、参考资料或额外脚本。一个结构清楚的 `SKILL.md` 就足够。

## 4. 五张需求卡

### 触发卡

只在用户明确调用 `/git-safe-submit` 或明确要求使用该 Skill 创建本地提交时使用。

### 输入卡

- 当前 Git 改动；
- 可选提交信息；
- 用户对提交范围的说明。

### 流程卡

1. 查看状态、diff、分支和最近提交；
2. 检查敏感或不相关文件；
3. 确认提交范围；
4. 只暂存相关文件；
5. 创建本地 commit；
6. 检查 commit 和剩余状态。

### 输出卡

- 提交范围；
- commit hash 和信息；
- 未提交的剩余改动；
- 明确说明没有 push。

### 边界与验收卡

- 不执行 `git push`；
- 不使用 `git add .` 隐式打包全部内容；
- 不提交密钥或敏感配置；
- 不绕过 hooks；
- 不修改 Git 配置；
- commit 创建成功且剩余状态清楚。

## 5. 怎样与 AI 一起创建

先把原 Command 交给 AI 分析，确认保留参数和 Bash Git 命令；再要求它只增加手动调用和安全边界，不把简单 Skill 过度拆分。
