# 案例 03：Claude Code 与 Codex 对比器

## 1. 原始表达特征

反复出现的问题包括：

- “Codex 和 Claude Code 怎么对应？”
- “Claude 的 Command 在 Codex 里是什么？”
- “两边的 Skill 能不能共用？”
- “核心知识点和重要区别给我详细列一列。”
- “我现在 Codex 用得更多，应该怎样选择？”

这类问题最容易因为版本更新、术语相似和路径不同而产生误导。

## 2. 结构化后的任务定义

> 针对一个明确场景，分别核对 Claude Code 与 Codex 当前官方资料，从概念、存放位置、触发方式、元数据、工具权限、项目指导和迁移成本等维度比较，最后给出适合当前用户的选择建议。

## 3. 原始表达容易遗漏什么

- 比较的是稳定概念还是当前版本功能；
- 要比较哪个具体能力；
- 是否需要给出来源；
- “对应”不等于“完全等价”；
- 用户最终需要的是学习建议还是迁移方案；
- 不能把 Claude 专属字段直接写进 Codex Skill。

## 4. 为什么先做成提示词

比较主题每次不同，而且当前资料可能变化。与其保存一份很快过时的结论，不如保存一条要求 AI 每次核对官方资料的比较提示词。

## 5. 五张需求卡

### 触发卡

用户要求比较 Claude Code 与 Codex 的功能、目录、概念或迁移方法时使用。

### 输入卡

- 要比较的能力；
- 当前使用场景；
- 更常用的平台；
- 是否准备迁移现有文件。

### 流程卡

1. 明确比较范围；
2. 查官方资料；
3. 分别描述两边原生概念；
4. 标注等价、近似和无直接对应；
5. 给迁移注意事项；
6. 结合用户场景推荐。

### 输出卡

- 一句话结论；
- 对照表；
- 核心差异；
- 不能直接照搬的部分；
- 选择建议；
- 来源和更新时间。

### 边界与验收卡

- 只使用当前官方资料解释产品行为；
- 不把相似名称当作完全等价；
- 不默认两边目录和 frontmatter 相同；
- 明确标注推断和不确定项。

## 6. 怎样与 AI 一起创建这条提示词

```text
我经常要比较 Claude Code 与 Codex，但担心版本变化和术语误导。先不要给具体结论，请帮我设计一条比较提示词应该固定检查哪些维度，以及怎样区分“完全对应”“功能近似”“没有直接对应”。
```

确认维度后：

```text
请生成一条可复用提示词，要求每次优先查询两边当前官方资料，输出对照表、迁移注意事项和针对用户场景的建议，不保存容易过时的固定结论。
```

## 7. 使用方式

把本次要比较的能力填入提示词，例如 Skills、项目指导、Hooks、MCP 或自动化。不要一次比较所有产品功能，否则结果容易过宽。

## 8. Codex 迁移说明

提示词本身平台无关。在 Codex 中使用时，应要求它优先查询 OpenAI 官方 Codex 文档；在 Claude Code 中使用时，应查询 Anthropic 官方文档。任何一方的文档都不能替另一方证明产品行为。
