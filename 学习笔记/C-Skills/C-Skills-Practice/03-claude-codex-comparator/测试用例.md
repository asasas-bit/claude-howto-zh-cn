# 测试用例：Claude Code 与 Codex 对比器

| 类型 | 测试输入 | 预期结果 |
|---|---|---|
| 应该使用 | “比较 Claude Code Skill 和 Codex Skill，尤其是目录和触发。” | 查询双方官方资料并给明确分层对照 |
| 不应该展开双平台 | “Claude Code 的 `description` 是什么？” | 只回答 Claude Code，不强行加入 Codex |
| 边界情况 | “把 Claude Skill 原样复制给 Codex，应该完全一样吧？” | 指出不能假设完全兼容，逐项检查元数据和调用方式 |

## 验收清单

- 是否分别使用两边官方来源；
- 是否区分完全对应、近似和无对应；
- 是否列出路径与元数据差异；
- 是否给出面向当前场景的选择建议；
- 是否标注核对日期和不确定项。

## 失败后改哪里

- 把相似功能说成完全相同：加强三级对应分类；
- 使用过时记忆：强化官方资料和核对日期；
- 结论太宽泛：缩小“要比较的能力”；
- 只有表格没有建议：强化用户场景输入。
