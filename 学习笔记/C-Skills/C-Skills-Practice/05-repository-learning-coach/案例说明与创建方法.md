# 案例 05：教程仓库学习教练

## 1. 原始表达特征

前面的典型问题是：

- “这个学习地图我能看懂顺序，但不知道具体怎样学。”
- “我是新手，之前只是跟 AI 聊聊天。”
- “应该在教程仓库练，还是找真实项目练？”
- “这个目录我看完了，但感觉没有真正学会。”
- “针对我当前水平，给我详细学习建议。”

核心问题不是缺少更多资料，而是缺少根据当前水平安排的练习、检查点和升级标准。

## 2. 结构化后的任务定义

> 读取当前教程仓库、路线图和已有学习笔记，诊断学习者处于“会看、会解释、会操作、会设计、会验收”的哪个阶段；为下一小段知识设计一个低风险、可手动完成的练习，并通过产物和复述题判断是否达到里程碑。

## 3. 为什么适合做成 Skill

- 每学一个目录都会重复；
- 需要读取仓库结构和现有笔记；
- 有稳定的诊断、练习和验收流程；
- 适合维护学习计划模板和水平判断规则；
- 需要避免一次安排太多高级内容。

## 4. 五张需求卡

### 触发卡

用户要求学习某个仓库、理解路线图、安排下一阶段练习或判断是否真正学会时使用。

### 输入卡

- 当前仓库或目录；
- 用户自述的水平和疑问；
- 已完成的练习或笔记；
- 可用时间和希望的节奏。

### 流程卡

1. 读取路线图、目录说明和相关示例；
2. 查看已有学习产物；
3. 诊断当前层级；
4. 只选择一个下一目标；
5. 设计“看懂—手做—解释—变式—验收”；
6. 记录完成证据和下一步。

### 输出卡

- 当前水平诊断；
- 为什么卡住；
- 一个主练习和一个变式；
- 手动步骤；
- 验收清单；
- 完成后再学什么。

### 边界与验收卡

- 不用大量新概念淹没用户；
- 不把“读过”当作“学会”；
- 优先在教程仓库做低风险练习，再迁移到真实项目；
- 不替用户完成明确要求亲手做的步骤；
- 以真实产物、复述和变式完成作为证据。

## 5. 怎样与 AI 一起创建

先让 AI 读取仓库并生成学习诊断，不创建 Skill；再确认水平判断和练习节奏；最后使用 `创建该Skill的AI提示词.md` 生成。
