# 可直接使用的提示词：小白概念解释器

## 可替换内容

- `[要学习的概念]`
- `[我当前的理解]`
- `[相关项目或材料]`
- `[希望的详细程度]`

## 完整提示词

```text
我正在学习：[要学习的概念]

我当前的理解是：
[我当前的理解]

相关项目、教程或材料：
[相关项目或材料；没有可写“无”]

希望的详细程度：
[简洁 / 适中 / 详细]

请把我当作已经有一点使用经验、但还没有形成完整知识体系的新手。不要只重新给我一个定义，请按下面的方式帮助我真正理解：

1. 先复述你理解到的我的观点，避免答非所问；
2. 把我的理解分成“正确”“部分正确但不完整”“需要纠正”三类；
3. 先用一句话给出最核心的结论；
4. 用通俗语言和一个贴近日常工作的类比解释；
5. 结合我提供的项目或材料给一个具体例子；
6. 如果存在相似概念，用表格说明区别、联系和使用场景；
7. 补充我没有意识到但真正重要的知识点；
8. 指出常见误区，以及误解后可能造成什么问题；
9. 如果内容属于可能变化的软件功能、CLI 或产品规则，先核对当前官方资料，并区分稳定原理与当前实现；
10. 最后给出一句便于记忆的心智模型，再出 1～3 个自测问题。

表达要求：
- 先说用途和结论，再讲术语；
- 第一次出现英文术语时给出中文解释；
- 不要为了完整而堆砌无关高级内容；
- 对不确定的地方明确说明，不要猜测；
- 如果我的理解总体正确，也要指出它成立的条件和边界。
```

## 一次性使用示例

```text
我正在学习：Claude Code 中 Command 与 Skill 的区别。

我当前的理解是：Command 就是一个写在 Markdown 里的提示词按钮；Skill 也是提示词，但是可以带脚本、模板和参考资料，所以 Skill 更复杂。

相关材料：当前仓库的 01-slash-commands 和 03-skills。

希望的详细程度：详细。

请按“小白概念解释器”的完整要求帮助我诊断和理解。
```
