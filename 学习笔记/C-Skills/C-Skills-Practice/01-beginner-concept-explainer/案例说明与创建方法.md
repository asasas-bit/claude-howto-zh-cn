# 案例 01：小白概念解释器

## 1. 原始表达特征

前面的提问中，经常出现这样的表达方式：

- “我大概能看懂，但是没有完全明白。”
- “你看看我的理解哪些对，哪些有问题。”
- “把相关知识点都给我讲一讲。”
- “不要讲得太复杂，小白一看也能懂。”
- “最好用表格、例子和一句话总结。”

这类需求的核心不是“搜索一个定义”，而是帮助学习者完成：理解现状诊断、纠错、补充、举例和复述。

## 2. 结构化后的任务定义

> 根据学习者自己的表述判断他已经理解了什么、误解了什么；先给结论，再用通俗语言、类比、对比表和贴近当前项目的例子解释；最后给出可以自行复述的心智模型和自测题。

## 3. 原始表达容易遗漏什么

- 没说清学习者当前水平；
- 没指定希望先纠错还是先完整讲解；
- 没区分稳定知识和可能变化的产品规则；
- 没要求引用当前官方资料；
- 没定义“讲明白”的验收方式；
- 没限制 AI 避免堆术语。

## 4. 为什么先做成提示词

它没有固定文件输出，也不依赖专属脚本或资料库。主题可能是 Skill、Hook、Git、MCP 或任意其他概念，一段结构清楚的提示词已经足够复用。

当以后形成固定课程、例题库和学习档案时，再考虑升级成 Skill。

## 5. 五张需求卡

### 触发卡

当用户说“没完全明白”“看看我的理解对不对”“用小白方式解释”时使用。

### 输入卡

- 必需：要学习的概念，以及用户当前的理解；
- 可选：项目背景、已读材料、希望的详细程度；
- 可发现：项目中的教程和示例。

### 流程卡

1. 复述用户当前理解；
2. 分出正确、部分正确和需要纠正的内容；
3. 给一句话结论；
4. 用类比和实际例子解释；
5. 补充边界、误区和选择方法；
6. 给自测或复述任务。

### 输出卡

- 理解诊断；
- 通俗解释；
- 对比或决策表；
- 实际例子；
- 常见误区；
- 一句话心智模型；
- 1～3 个自测问题。

### 边界与验收卡

- 不假装用户完全没有基础；
- 不重复堆砌定义；
- 当前产品规则需要核对官方资料；
- 解释后，用户应能用自己的话复述区别和使用场景。

## 6. 怎样与 AI 一起创建这条提示词

第一轮只说明目标：

```text
我经常会把自己对一个概念的理解说出来，请你判断哪些正确、哪些不完整，再用小白能懂的方式解释。先不要直接写最终提示词，请帮我梳理它需要哪些输入、输出和验收标准。
```

第二轮审查结构：

```text
把它设计成一条可重复使用的提示词，不创建 Skill。请确保包含理解诊断、纠错、类比、实例、误区和自测，但不要让格式过度复杂。
```

第三轮生成并试用：

```text
现在生成完整提示词，并拿“Command 与 Skill 的区别”做一次试运行。运行后指出提示词哪里还可以改进。
```

## 7. 使用方式

打开 `可直接使用的提示词.md`，替换其中的主题、当前理解和背景材料，然后粘贴给 Claude Code、Codex 或普通对话模型。

## 8. Codex 迁移说明

这是平台无关提示词，不需要修改为 Codex Skill。直接在 Codex 对话中使用即可。只有当它以后需要长期课程资料、测试记录或脚本时，再包装成 Codex Skill。
