# 学习笔记写作规则

## 面向读者

- 默认读者已经使用过 AI 对话，但没有完整的工程化知识体系。
- 不把读者当作完全零基础，也不假设读者熟悉专业缩写。

## 表达顺序

1. 先说用途和结论；
2. 再解释原理；
3. 再给真实例子；
4. 最后补充高级内容和边界。

## 概念解释

- 第一次出现英文术语时给出自然中文解释。
- 使用类比时明确类比的边界，避免把类比当成严格定义。
- 优先结合当前项目中的真实文件和命令。
- 用户已有理解正确时明确肯定，同时说明成立条件。

## 命令风格

- 用户使用 PowerShell 时，手动命令优先采用 PowerShell 可直接运行的写法。
- 简单 `cp 源 目标` 能工作时无需强制展开成很长的 `Copy-Item`。
- 不因外层终端是 PowerShell，就自动把 Skill 内部可工作的 `Bash(git ...)` 改掉。
- 路径使用真实示例，并清楚标注需要替换的部分。

## 文档质量

- 标题应直接反映主题。
- 表格只用于真正需要对照的信息。
- 不重复同一个结论来制造篇幅。
- 不保留 `[请填写]`、`TODO` 或其他占位符。
- 当前产品功能需要说明资料来源或核对日期。

## 安全

- 删除密码、API key、token、邮箱验证码和私人账号信息。
- 不记录一次性授权内容。
- 未经要求不提交或推送 Git。
