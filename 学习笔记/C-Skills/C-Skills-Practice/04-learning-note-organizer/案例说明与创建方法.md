# 案例 04：学习笔记整理器

## 1. 原始表达特征

前面的聊天中多次出现：

- “把刚才讲的内容完整整理成一个 MD。”
- “帮我命个名，保存到学习笔记下面。”
- “按表格列出来，让小白一看就懂。”
- “把操作步骤、原理和不足都补充完整。”
- “只创建笔记，不要提交或推送。”

这已经不是一次性写作请求，而是稳定的内容整理、文件命名、保存和验证流程。

## 2. 结构化后的任务定义

> 把当前对话、用户提供的材料和项目内相关文档，整理成适合新手复习的 Markdown；先诊断用户真正想学什么，再组织概念、步骤、例子和误区；保存到指定学习笔记目录，避免覆盖和泄露敏感信息，最后重新读取并验证结构。

## 3. 原始表达容易遗漏什么

- 文件名和目录冲突怎样处理；
- 是否允许补充项目资料；
- 是否应该保留用户的原始疑问；
- 什么叫“完整”但不过度重复；
- 保存后怎样验证；
- 是否允许自动 commit 或 push；
- 敏感信息和一次性上下文怎样处理。

## 4. 为什么适合做成完整 Skill

它具有明显的 Skill 特征：

- 高频重复；
- 有稳定输入、流程和输出；
- 输出结构适合做模板；
- 写作规则适合做参考资料；
- Markdown 结构检查适合用确定性脚本；
- 涉及文件写入和安全边界。

## 5. 五张需求卡

### 触发卡

当用户要求整理学习笔记、把当前讨论保存成 Markdown、沉淀知识点或生成复习材料时使用。

### 输入卡

- 必需：当前对话或指定材料；
- 可选：目标目录、文件名、目标读者和详细程度；
- 可发现：已有学习笔记结构、相关教程和项目命名习惯。

### 流程卡

1. 确认知识主题和用户当前水平；
2. 读取相关材料；
3. 区分核心结论、原理、步骤、例子和误区；
4. 按模板生成内容；
5. 选择清楚且不冲突的文件名；
6. 保存后重新读取；
7. 运行结构校验；
8. 汇报路径和检查结果。

### 输出卡

- 一个 Markdown 文件；
- 先结论后解释；
- 包含核心概念、步骤、例子、误区和自检；
- 在聊天中只汇报路径和摘要，不重复粘贴全文。

### 边界与验收卡

- 不覆盖已有文件；
- 不写入密码、密钥或隐私；
- 不自动 commit 或 push；
- 所有引用路径存在；
- 校验脚本通过；
- Git 状态只出现预期文件。

## 6. 从 V0.1 到完整版本

### V0.1：只有 `SKILL.md`

先把触发、流程、输出和安全边界跑通。

### V0.2：增加模板

实际使用后发现每篇笔记都需要相似栏目，因此增加 `templates/learning-note-template.md`。

### V0.3：增加参考规则

把“先结论后解释”“适合新手”“PowerShell 命令风格”等稳定规则拆到 `references/writing-rules.md`。

### V0.4：增加校验脚本

为了确定性检查标题和占位符，增加 `scripts/validate-note.ps1`。脚本只读目标文件，不修改内容。

## 7. 怎样与 AI 一起创建

建议分四轮：

1. 用五张卡确认需求，不创建文件；
2. 先设计 V0.1，解释为什么暂不需要资源；
3. 根据真实使用问题增加模板、参考规则和校验脚本；
4. 用正常、误触发和边界场景测试。

完整的创建请求见 `创建该Skill的AI提示词.md`。

## 8. 安装到 Claude Code 项目

本案例保存在学习笔记里，不会自动生效。需要安装时，在仓库根目录执行：

```powershell
mkdir .\.claude\skills -Force
cp -Recurse .\学习笔记\C-Skills\C-Skills-Practice\04-learning-note-organizer\claude-skill\learning-note-organizer .\.claude\skills\
```

然后重启 Claude Code，或在当前版本支持时重新加载 Skills。

## 9. Codex 迁移说明

- 保留核心工作流、参考资料和校验脚本；
- Codex `SKILL.md` 的 frontmatter 只保留 `name` 和完整的 `description`；
- 模板属于最终输出骨架时，可移动到 `assets/`；作为阅读规则时可保留在 `references/`；
- 个人安装到 `$CODEX_HOME/skills/learning-note-organizer/`；
- 不照搬 Claude 专属变量或调用语法，改为在 Codex Skill 中用相对路径说明资源；
- 不假设安装后一定通过同名斜杠命令调用，以 Codex 当前 Skill 发现和触发方式为准。
