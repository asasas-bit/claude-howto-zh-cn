# 从历史对话沉淀提示词与 Skills：案例库总览

## 一、这套案例库解决什么问题

这套案例不是凭空编造的“万能 Skill”，而是从前面反复出现的真实提问中提炼出来的。

你的原始表达通常具有这些特点：

- 先说自己哪里没明白，再补充大量背景；
- 希望 AI 纠正理解，而不是只给结论；
- 经常要求用小白能懂的方式解释；
- 希望看到具体 PowerShell 操作，而不是抽象说明；
- 有时要求 AI 不要代替操作，只给手动步骤；
- 经常把聊天内容整理成 Markdown 并保存到学习笔记；
- 反复比较 Command、Skill、Claude Code 和 Codex；
- 希望 AI 先帮助定义，再创建，最后解释为什么这样设计；
- 重视 Git 安全，不希望未经要求自动提交或推送。

这些表达并不是“说得不好”，而是典型的口语化需求。案例库的价值，是把口语化需求进一步整理为：

```text
重复问题
    ↓
稳定目标
    ↓
输入、流程、输出、边界、验收
    ↓
选择 Prompt / Command / Skill / Hook / MCP
    ↓
形成可复用成品
```

## 三、为什么前三个先做成提示词

前三个任务具有共同特点：

- 不一定需要读固定资料；
- 不一定需要创建文件；
- 没有稳定脚本或模板依赖；
- 输入主题每次都可能不同；
- 一段结构清楚的提示词已经可以显著改善结果。

因此先做成提示词，成本最低，也方便继续观察实际使用情况。

如果以后连续使用多次，并且出现固定资料、模板或验证步骤，再升级成 Skill。

## 四、为什么后七个适合做成 Skill

这些任务已经具有一个或多个 Skill 特征：

- 会反复出现；
- 有稳定的多步骤流程；
- 需要固定模板或参考资料；
- 涉及文件保存、检查或 Git 操作；
- 需要安全边界；
- 希望在合适场景下被自动发现，或者通过固定名称手动调用。

Skill 的价值不是“比提示词高级”，而是把一套已经稳定的做事方式保存下来。

## 五、载体选择速查表

| 情况 | 首选载体 | 原因 |
|---|---|---|
| 只用一次、输入变化很大 | 当前对话提示 | 不值得长期维护 |
| 反复使用同一段表达 | 可复制提示词 | 简单、透明、修改方便 |
| 明确按一次就执行一个操作 | Command 或手动 Skill | 强调用户主动触发 |
| 多步骤流程、需要模板和资料 | Skill | 适合按需加载和长期复用 |
| 必须确定执行的机械操作 | Script，并由 Skill 调用 | 比临场生成命令更稳定 |
| 某事件发生时必须自动检查 | Hook | 不是靠用户记得调用 |
| 需要读取或操作外部系统 | MCP / Connector | 解决实时数据和授权问题 |
| 整套能力要安装、分发 | Plugin | 打包 Skill、Hook、MCP 等能力 |

## 六、暂时不建议沉淀的内容

### 1. 单个知识点的一次性解释

例如只问一次某个 YAML 字段是什么意思，不必单独创建 Skill。可以直接使用 `beginner-concept-explainer` 提示词。

### 2. 项目长期事实

例如仓库固定使用 PowerShell、测试命令是什么，更适合写进 `CLAUDE.md` 或 `AGENTS.md`，而不是每次触发一个 Skill。

### 3. 尚未真实发生的复杂自动化

不要为了展示 `scripts/`、Hooks 或 MCP 而虚构需求。先观察重复问题，再决定是否增加。

### 4. 高风险的一键提交并推送

本案例只沉淀本地安全提交；自动 push、发布、删除等操作需要更严格的确认和权限设计。

## 七、每个案例怎样阅读

建议按下面顺序打开每个子目录：

1. 阅读 `案例说明与创建方法.md`，理解为什么这样定义；
2. 对照自己的原始表达，找出缺少的输入、边界和验收；
3. 阅读可直接使用的提示词，或 `创建该Skill的AI提示词.md`；
4. 查看最终成品；
5. 阅读 `测试用例.md`，理解怎样判断好坏；
6. 最后再决定是否复制安装。

## 九、平台范围

- 完整 Skill 按 Claude Code 项目 Skill 结构编写；
- 所有案例只保存在学习笔记中，不会自动安装；
- 安装时再复制到 `.claude/skills/<skill-name>/`；
- Codex 部分只解释迁移原则，不重复制造一套相同文件；
- Codex Skill 的个人安装位置按 `$CODEX_HOME/skills`（通常为 `~/.codex/skills`）理解；
- Claude 专属 frontmatter 不直接照搬到 Codex；
- 不假设 Claude Code 和 Codex 有完全相同的斜杠调用体验。

## 十、最终学习标准

看完这套案例后，目标不是背下所有文件，而是能够回答：

> 这个需求为什么值得沉淀？为什么选择提示词或 Skill？它需要什么输入？按什么流程完成？哪些事情不能做？怎样证明做对了？
