# 案例 08：重复工作流挖掘器

## 1. 原始表达特征

本次提出的需求本身就是一个可复用工作流：

- 回顾前面所有聊天；
- 找出反复提问和重复动作；
- 判断哪些只需要提示词；
- 判断哪些已经形成稳定 Skill；
- 区分简单与复杂工作流；
- 说明怎样定义、怎样和 AI 一起创建；
- 生成可以直接使用的成品。

很多人知道重复工作可以自动化，但很难从自然语言记录中发现“自己到底重复了什么”。

## 2. 结构化后的任务定义

> 分析一段时间内的聊天记录、笔记、任务或项目产物，提取重复的目标、输入、步骤、输出和风险；合并只是表达不同但本质相同的任务；根据频率、稳定度、确定性、事件触发和外部数据依赖，分类为 Prompt、项目指导、Command、Skill、Script、Hook、MCP 或 Plugin；为优先候选生成需求卡、创建路径和测试用例。

## 3. 为什么是复杂 Skill

- 输入通常较长且杂乱；
- 需要区分主题重复和动作重复；
- 需要避免把所有内容都产品化；
- 要在多种载体之间作判断；
- 要输出总表和单个候选规格；
- 可能进一步生成多个 Skill，但必须先设确认闸门。

## 4. 五张需求卡

### 触发卡

用户要求复盘聊天、整理重复工作、寻找可复用提示词或 Skill、规划自动化沉淀时使用。

### 输入卡

- 一段时间内的聊天、笔记、日志或任务列表；
- 当前工作环境和常用工具；
- 用户希望沉淀的范围；
- 风险容忍度和是否允许创建文件。

### 流程卡

1. 读取来源并建立证据索引；
2. 提取重复目标、动词、输入和输出；
3. 合并同义任务；
4. 区分知识主题与工作流；
5. 使用判断规则分类；
6. 排序并说明不建议沉淀的项；
7. 为候选生成单项规格；
8. 用户确认后才创建成品。

### 输出卡

- 候选总表；
- 每项的重复证据；
- 推荐载体和理由；
- 复杂度、价值、风险和优先级；
- 单项需求卡、创建方法和测试；
- 暂不沉淀清单。

### 边界与验收卡

- 不把一次性问题伪装成高频；
- 不因为出现英文术语就判断为 Skill；
- 不读取未授权的私人记录；
- 不直接批量创建候选；
- 结论能追溯到输入证据；
- 相似候选已合并，载体选择有理由。

## 5. 怎样与 AI 一起创建

先只做分析总表，观察 AI 是否正确合并重复问题。第二轮选择优先候选并填写规格。第三轮用户确认后，才为选中的候选生成提示词或 Skill。
