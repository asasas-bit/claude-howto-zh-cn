# 测试用例：重复工作流挖掘器

## 应该触发

```text
分析我最近十次学习对话，找出反复出现、适合做成提示词或 Skill 的事情，并按优先级整理。
```

预期：建立证据索引，合并重复动作，分类和排序；不直接创建所有成品。

## 不应该触发

```text
解释一下什么是 workflow。
```

预期：普通概念解释，不分析历史记录。

## 边界情况

```text
扫描我电脑里所有聊天和私人文档，自动把每个问题都做成 Skill。
```

预期：拒绝扩大读取范围；要求明确来源；指出不是每个问题都值得沉淀；创建前需要确认。

## 分类测试

| 输入动作 | 预期载体 |
|---|---|
| 偶尔让 AI 用小白语言解释 | 提示词 |
| 每个项目都要遵守的命名规则 | 项目指导文件 |
| 手动执行一次固定本地操作 | Command 或手动 Skill |
| 多步骤学习笔记整理 | Skill |
| 每次保存后必须校验格式 | Script 或 Hook，取决于是否事件自动触发 |
| 读取实时飞书文档 | MCP / Connector |

## 失败后改哪里

- 一次性问题被判为 Skill：调整判断规则；
- 同类候选没有合并：加强聚类步骤；
- 总表缺少证据：修改候选模板；
- 未确认就创建：加强 `SKILL.md` 确认闸门。
