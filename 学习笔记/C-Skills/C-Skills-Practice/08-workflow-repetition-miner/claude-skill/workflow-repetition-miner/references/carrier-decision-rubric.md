# 重复工作载体判断规则

## 第一步：确认是否真的重复

| 证据 | 判断 |
|---|---|
| 只出现一次 | 默认不沉淀，除非风险很高或即将频繁使用 |
| 出现两次 | 候选，继续观察 |
| 出现三次以上 | 优先分析是否形成稳定流程 |

频率不是唯一标准。低频但高风险的发布检查，也可能值得脚本或 Hook。

## 第二步：区分知识与动作

- 反复问同一主题：可能需要学习笔记、参考资料或解释提示词。
- 反复要求同一结果并经过相同步骤：更接近工作流。

## 第三步：选择最小载体

| 特征 | 推荐载体 |
|---|---|
| 临时、开放、无固定资源 | 当前提示或可复制 Prompt |
| 项目长期事实和规范 | `CLAUDE.md` / `AGENTS.md` |
| 用户明确手动触发的短操作 | Command 或手动 Skill |
| 稳定多步骤、带模板或资料 | Skill |
| 机械、确定、易错 | Script |
| 生命周期事件自动执行 | Hook |
| 外部实时数据或授权动作 | MCP / Connector |
| 多能力安装与分发 | Plugin |

## 第四步：复杂度

- 简单：单个 Prompt 或单文件 Skill。
- 中等：Skill + 一个模板或参考文件。
- 复杂：多阶段决策、多个资源、脚本、权限或外部系统。

## 第五步：优先级

优先创建：

- 高频；
- 目标清楚；
- 输出容易验收；
- 风险低；
- 能明显减少重复说明。

暂缓创建：

- 边界不清；
- 还没有真实例子；
- 依赖未解决的外部权限；
- 自动化收益小于维护成本；
- 高风险但没有可靠验证。
