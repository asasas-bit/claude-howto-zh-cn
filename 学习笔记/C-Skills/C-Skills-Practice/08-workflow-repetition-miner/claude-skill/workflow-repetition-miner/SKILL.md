# Workflow Repetition Miner / 重复工作流挖掘器

开始时读取：

- `${CLAUDE_SKILL_DIR}/references/carrier-decision-rubric.md`
- `${CLAUDE_SKILL_DIR}/templates/workflow-candidate-catalog.md`

为单个候选展开时读取：

- `${CLAUDE_SKILL_DIR}/templates/candidate-spec.md`

## 第一阶段：确定范围

1. 明确要分析的时间、对话、目录或文件。
2. 只读取用户提供或明确授权的来源。
3. 记录用户常用平台、终端、项目类型和风险偏好。
4. 不默认访问私人聊天、云盘或外部系统。

## 第二阶段：建立重复证据

1. 提取反复出现的目标、动作动词、输入、输出和限制。
2. 将不同说法但本质相同的动作合并。
3. 区分：反复学习同一个知识主题，还是反复执行同一套流程。
4. 每个候选至少列出两个来源证据；不足时标为“待观察”。

## 第三阶段：选择载体

使用判断规则评估：

- 频率；
- 输入与输出稳定度；
- 是否需要资源；
- 是否要求确定性执行；
- 是否由事件自动触发；
- 是否依赖外部实时数据；
- 风险和权限。

选择最小可用载体，不把所有重复文字都做成 Skill。

## 第四阶段：输出和排序

1. 使用候选总表输出全部结果。
2. 按“高价值、低风险、定义清楚”优先。
3. 单独列出暂不沉淀的内容及理由。
4. 对优先候选使用单项规格模板，生成五张卡、创建方法和测试。

## 第五阶段：确认后创建

分析结束不等于获得批量创建授权。

- 先让用户确认候选、平台和交付深度。
- 只创建用户确认的成品。
- 保留用户已有修改。
- 不自动 commit、push、发布或访问外部系统。

## 完成标准

- 每个候选可以追溯到证据；
- 相似候选已经合并；
- 载体选择有明确理由；
- 暂不沉淀项没有被忽略；
- 优先候选有可执行规格和三类测试。
