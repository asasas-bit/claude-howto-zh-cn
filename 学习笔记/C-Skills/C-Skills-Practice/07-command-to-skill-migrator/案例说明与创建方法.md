# 案例 07：Command 转 Skill 迁移器

## 1. 原始表达特征

前面的真实任务包括：

- 读取 `01-slash-commands/commit.md`；
- 判断它与 Skill 的关系；
- 把它变成 Claude Code Skill；
- 用户先手动练习，AI 不直接操作；
- 讨论 `Bash(git ...)` 是否必须改成 PowerShell；
- 保留简单 `cp` 操作；
- 解释迁移后为什么这样设计。

这些步骤已经形成稳定的“分析—判断—迁移—校验—教学”工作流。

## 2. 结构化后的任务定义

> 读取一个 Claude Code Slash Command，分析触发、参数、动态上下文、工具权限和安全风险；判断是否值得升级为 Skill；在保留原行为的前提下设计目标目录和 frontmatter；根据用户选择提供手动步骤或实施迁移；最后验证 Skill 发现、调用和副作用边界。

## 3. 为什么是复杂 Skill

- 涉及旧结构与新结构映射；
- 需要处理参数、文件引用和动态 shell 注入；
- Bash、PowerShell 和外层终端容易混淆；
- 可能修改项目文件；
- 需要手动教学和直接实施两种模式；
- 需要兼容和安全判断。

## 4. 五张需求卡

### 触发卡

用户要求把 `.claude/commands` 或命令 Markdown 转成 Skill、解释迁移或审查兼容性时使用。

### 输入卡

- Command 文件路径；
- 目标平台和安装范围；
- 手动教学还是直接实施；
- 是否保留手动调用；
- 当前 Windows、Git Bash 或 PowerShell 环境。

### 流程卡

1. 读取源文件和项目约束；
2. 分析功能、参数、工具和动态值；
3. 判断是否值得迁移；
4. 设计目标名称和目录；
5. 输出迁移报告；
6. 按模式提供步骤或实施；
7. 校验文件、发现、调用和安全边界。

### 输出卡

- 迁移必要性结论；
- 字段和行为映射；
- 风险说明；
- 目标目录；
- 手动 PowerShell 步骤或实际 Skill；
- 测试结果。

### 边界与验收卡

- 不删除原 Command；
- 不因为外层 PowerShell 就盲目改掉 Bash；
- 不扩大原命令权限；
- 高风险命令默认手动调用；
- 不自动 commit 或 push；
- 源行为与迁移后行为可对照。

## 5. 怎样与 AI 一起创建

先让 AI 只读分析源 Command 并填写迁移报告。确认名称、调用方式和 shell 选择后，再选择“只给手动步骤”或“直接实施”。

## 6. 安装到 Claude Code 项目

```powershell
mkdir .\.claude\skills -Force
cp -Recurse .\学习笔记\C-Skills\C-Skills-Practice\07-command-to-skill-migrator\claude-skill\command-to-skill-migrator .\.claude\skills\
```

## 7. Codex 迁移说明

这个 Skill 本身是 Claude Command 迁移工具。迁移到 Codex 后，应把目标改为“提取可复用工作流并重写为 Codex Skill”，而不是复制 Claude frontmatter。

- Codex frontmatter 只保留 `name`、`description`；
- Claude 的 `allowed-tools`、`argument-hint`、动态 `!` 注入等需要逐项重新设计；
- 个人安装到 `$CODEX_HOME/skills/command-to-skill-migrator/`；
- 迁移报告仍可复用，但规则参考应替换为当前 Codex 规范；
- 不假设 Codex 通过 Claude 的 Slash Command 目录发现文件。
