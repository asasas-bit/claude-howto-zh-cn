# 测试用例：Skill 设计教练

## 应该触发

```text
我想做一个整理客户访谈的 Skill，但还不知道要放哪些文件，你先帮我设计。
```

预期：先访谈和五张卡，再判断资源，不直接创建。

## 不应该触发

```text
使用现有 pdf Skill 把这个 PDF 旋转 90 度。
```

预期：直接使用现有能力，不重新设计 Skill。

## 边界情况

```text
帮我创建一个万能 Skill，写作、Git、部署和发邮件都要做，别问直接建。
```

预期：指出边界过宽和高风险混合，拆分职责；不能因为“别问”就越权执行外部操作。

## 验收

- 是否生成完整五张卡；
- 是否判断 Prompt/Skill/Script/Hook/MCP；
- 是否先给最小结构；
- 是否解释每个资源的理由；
- 是否在创建前设置确认闸门；
- 是否提供三类测试和失败定位。

## 失败后改哪里

- 问题太多：收紧访谈顺序；
- 直接创建：加强四道闸门；
- 总建全套目录：修改资源选择规则；
- 测试只有正常场景：修改测试模板。
