## 一句话结论

**记忆不是一个文件，而是一条"原始对话（L0）→ 原子卡片（L1）→ 项目规矩（L2）→ 个人风格（L3）"的提炼流水线。** CLAUDE.md 是写给 AI 的岗位说明书，settings.json 是 App 的设置面板（**不是记忆**），auto memory 是 AI 自己记的工作小卡片，session 是今天的班次，而每天写日报、整理笔记就是在带 AI 做每日复盘（Anthropic 说的 Dreaming）。

## 核心概念：7 个问题逐个讲明白

### Q1：记忆是不是"全局 + 项目"两个 MD 文件？

**一句话结论：不是两个文件，是"四层说明书 + 一套小卡片"，它们是拼在一起给 AI 看的，不是互相替换。**

对的部分：personal-CLAUDE.md 就是**全局个人层**（`~/.claude/CLAUDE.md`，记你这个人的习惯、偏好、"我是谁"），project-CLAUDE.md 就是**项目层**（仓库根目录 `CLAUDE.md`，记这个项目怎么干活）。"记个人习惯、通用要求、人的标签特色、产品基础描述"这个内容直觉是对的。

要纠正的：远不止两个文件——

| 层级 | 文件在哪 | 写什么 | 随项目走吗 |
|---|---|---|---|
| ① 托管层 Managed | 系统目录（公司电脑管理员下发） | 公司硬性规定 | —— |
| ② 用户层 User | `~/.claude/CLAUDE.md` | **你这个人**的习惯：中文回答、先讲用途、工厂/外贸背景 | 不随项目，所有项目都读 |
| ③ 项目层 Project | 项目根目录 `CLAUDE.md` | **这个项目**的规矩：兼容性优先、哪些词不许翻译、提交流程 | 提交 git，团队共享 |
| ④ 本地层 Local | 项目里 `CLAUDE.local.md` | 你在这个项目里的**私人**备注，如"我本机 uv 路径有坑" | 不提交 git，只属于你 |
| ⑤ 目录级 | 子目录里的 `CLAUDE.md`（见 Q2） | 只在某个子目录干活时才生效的规矩 | 随项目 |
| ⑥ auto memory | `~/.claude/projects/<项目>/memory/` 下一堆小 md | AI 自己记的小卡片（见 Q4） | 按项目隔离 |

**类比**：新员工上班第一天，桌上摊着四份文件——**公司章程**（托管层）、**你给所有下属定的工作习惯**（用户层）、**这个项目的作业指导书**（项目层）、**你贴在显示器边上的私人便签**（本地层）。他四份全看；便签和指导书说法不一样时，以便签（最新、最具体）为准。

**边界和误区**：
- 这四层是"**规则和说明书**"——告诉 AI **怎么干活**，不是资料库。别把长篇素材塞进去（单个 CLAUDE.md 建议 ≤200 行）。
- 项目层 vs 本地层的区别就是 **git**：能给团队看的写项目层；只对你这台电脑/你个人成立的写 local 层。

### Q2：目录级记忆 = 给每个 skill / 子 Agent 挂记忆？

**一句话结论：目录级 CLAUDE.md 是按"文件系统文件夹"触发的，不是按 skill 或子 Agent 挂的；但"每个子功能有自己的记忆"这个直觉方向对——实现机制是另外三套东西。**

**第一套：目录级 CLAUDE.md——按"你在哪个文件夹干活"触发。**
比如有个 `02-memory/CLAUDE.md`，只有 AI 在 `02-memory/` 目录里改文件时才拼进来；在 `10-cli/` 干活就不加载。`02-memory/directory-api-CLAUDE.md` 示例演示的就是"改 `src/api/` 下代码时，API 专属规范才生效"。

**类比**：不是"每个员工带一份小抄"，而是**每个车间门口贴着该车间的安全规程**——进哪个车间才看哪张，从来不进的车间，规程不占你脑子。

**第二套：skill 自己带说明书（SKILL.md）。**
每个 skill 目录里的 `SKILL.md` 就是这个技能的"记忆"，但平时**不占上下文**——AI 只看到一行技能名+一句话描述（书架上只看书名），确定要用才抽出来读（这就是"渐进式暴露"，Q7 细讲）。

**第三套：子 Agent（subagent）的记忆。**
新版本里 subagent 可以有**自己的 auto memory**（长期项目用）；但默认子 Agent 是"白纸开工"，不继承主对话上下文，除非开 `context: fork`。这跟目录级 CLAUDE.md 完全是两条路。

| 你以为的 | 实际机制 | 触发时机 |
|---|---|---|
| 每个子功能挂记忆 | 子目录 CLAUDE.md | AI 在那个文件夹干活时 |
| 每个 skill 挂记忆 | skill 目录里的 SKILL.md + references | 调用这个 skill 时才读 |
| 每个子 Agent 挂记忆 | subagent 独立 auto memory / `context: fork` | 子 Agent 开工时 |

**误区**：别把"记忆"理解成一个实体文件。在 Claude Code 里，"记忆"是**一整套在不同时机往上下文里放东西的机制**——这正是 Q7 融合不起来的根因。

### Q3："拼接不覆盖、向上查找、local 接在后面" + `--add-dir`

**一句话结论：几层文件不是谁覆盖谁，而是全部拼起来、按"从笼统到具体"排序，越具体的排越后、话语权越大。**

加载时的排列规则：

1. **从工作目录向上查找**：在 `d:\cc\claude-howto-zh-cn\02-memory\` 启动 Claude，它从当前文件夹开始一级级往上找：`02-memory\CLAUDE.md`（如有）→ 仓库根 `CLAUDE.md` → 用户目录 `~/.claude/CLAUDE.md`，一路经过的 CLAUDE.md **全部收集**。
2. **拼接，不覆盖**：像 Word 邮件合并一样**拼成一份长文档**塞进上下文。顺序：托管层 → 用户层 → 项目层 → 目录层；**同目录下 `CLAUDE.local.md` 接在 `CLAUDE.md` 后面**。
3. 为什么 local 排最后？AI 读指令时**后出现的、更具体的内容权重更高**。私人便签压在作业指导书后面，等于"通用规矩如上，我个人再补一句最新情况"。

**类比**：新员工先读公司章程（最笼统），再读你的个人工作习惯，再读项目作业指导书，最后看到压在最上面的便签（最具体、最新）。四份一张没扔；便签说"本周特殊，提交前先喊我一声"，就按便签来。

**`--add-dir` 是干嘛的**：正常 Claude 只能看到当前项目目录。同时在两个相关仓库干活（monorepo，或主项目+旁边的配置仓库）时，启动加 `claude --add-dir 隔壁仓库路径`（还需设环境变量开关 `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`），就能把**隔壁目录的 CLAUDE.md 也借过来一起拼上**，AI 也能读那个目录的文件。

**类比**：平时在自己车间干活只看自己车间规程；临时跨车间协作，跟门卫说"把二车间规程也给我一份"（`--add-dir`），二车间规程也摊到桌上。

**边界**：这是"多目录协作"的高级功能，单仓库学习用不上，知道它是"把隔壁仓库拉进上下文"即可。

### Q4：auto memory 和 HERMES 自动记忆是一回事吗？

**一句话结论：理念一模一样（AI 自己写、跨会话积累、越用越懂你），但 Claude 这套是"摊开在文件系统里的透明笔记本"，不是藏在数据库里的黑箱；而且它是"干活时顺手记"，目前没有后台自动整理。**

对的部分："越用越了解自己"成立。对话中你告诉它一个长期事实（"我用 PowerShell""这个项目校验命令是 uv run ..."），或它自己发现值得记住的事，就写成一个小 md 存起来，**下次在这个项目开新对话自动带上**。

四个区别：

1. **它是文件，不是黑箱**。存在 `~/.claude/projects/<项目代号>/memory/`：一个 `MEMORY.md` 当**索引本**（每行一条记忆标题+一句话说明），每条具体记忆是**一个单独小 md**，一文件一件事。可以直接打开看、改、删。这就是 Anthropic 演讲说的"**文件系统式记忆是当前最佳实践**"：Markdown + 普通文件搜索，AI 用最普通的文件工具就能读写，不依赖专用记忆系统。
2. **按项目隔离**。这个仓库的记忆和别的项目分开，不是一份全局记忆到处用。全局习惯放 `~/.claude/CLAUDE.md`——分工：CLAUDE.md 管"规矩"，auto memory 管"沉淀下来的事实和经历"。
3. **它是"带内记忆"（in-band）**：干活的同一个对话里顺手记，不是 HERMES 那种后台进程自动升级，也不会主动扫描所有历史对话。
4. **有容量上限**：每次开对话，`MEMORY.md` 索引只加载**前 200 行或前 25KB**（先到为准）。索引堆太长，后面的条目 AI 看不到。

"我自己维护就是想到了就往里加"——**对，就这么用**：直接说"记住：……"，或手动往 memory 目录写文件都行。坑见后面"常见误区"。

**和 HERMES 的类比**：HERMES 像**每晚自己复盘日记、还会自己修订笔记**的助理；Claude 的 auto memory 像**工作中随手把要点抄进档案卡、卡片盒完全敞开**的助理——抄卡片两者都有；"晚上自己复盘整理"这一步 Claude 目前**没有内置**（Q7 讲怎么自己搭）。

### Q5：session（会话）是什么？

**一句话结论：session 就是"一次连续对话"——从启动 Claude（或开新对话）到退出/清空，这一整段就是一个 session，类比"上一个班次"。**

- **打开 Claude Code 开始聊** = 上班打卡，一个 session 开始。
- **这班里聊的所有内容**（你说的话、它读的文件、改的代码、跑的命令）= 工作现场，全在"上下文"里。
- **关掉窗口 / `/clear`（清空）** = 下班。撤掉的是"现场"，不是"档案"：CLAUDE.md 和记忆是档案，下个班次重新读；这班里临时聊的东西，不带档案就没了。

| 命令/功能 | 干什么 | 类比 |
|---|---|---|
| `claude -c`（--continue） | 接着**最近一次**对话继续 | 第二天上班"把昨天的摊子原样摆回来" |
| `claude -r` / `/resume` | 从**历史会话列表**挑一个恢复 | 翻排班记录，"把上周三那个班接上" |
| checkpoints（`/rewind` 或连按两次 Esc） | 回到这个班**某个时间点**（对话+文件改动一起回退） | 班里有"存档点"，走错路读档 |
| `/clear` | 清空当前班，开新班 | 这个活儿干完，收拾桌子接下一个 |

所以"全局命令可用 session""当前 session 切 memory"这类话，意思无非是：**有些设置/操作只对这一班生效，有些是跨班次的档案**。

**关键对应**（Q7 还要用）：每个班的**完整对话记录都存在电脑上**（`~/.claude/projects/` 下的 `.jsonl` 文件）。`-c`、`/resume`、checkpoint 全靠这些存档——这就是腾讯文章里 **L0 原始对话**的真实存放点。

### Q6：`/config`、settings.json、cleanupPeriodDays —— 这不是记忆！

**一句话结论：settings.json 是 Claude Code 这个 App 的"设置面板"（管权限、模型、钩子这些程序行为），CLAUDE.md 是"写给 AI 看的岗位说明书"（管内容和规矩）——把这两样混成一个，是这轮困惑里最关键的结。**

最重要的区分：

| | CLAUDE.md / auto memory | settings.json |
|---|---|---|
| 本质 | 给**AI 大脑**看的内容 | 给**程序**看的设置 |
| 管什么 | 怎么干活、偏好、规矩、事实 | 权限弹窗、用哪个模型、hooks（钩子，事件触发的脚本）、环境变量 |
| 谁读它 | 模型（当上下文读） | Claude Code 程序（当配置解析） |
| 类比 | 岗位说明书 | App 设置页（像手机设置里"允许 App 用摄像头吗"） |

**`/config` 是什么**：对话里输 `/config` 弹出设置界面，勾选"这个命令别再问我了""用哪个模型"。**v2.1.119 的意义**：以前在 /config 里改的可能只对当前会话生效，从那以后改了会**真正写进 settings.json、长期生效**。"设置权限时看到过 config 文件"——看到的就是 settings.json。

**settings.json 三层，优先级从高到低**：

1. 公司托管设置（managed-settings.json，管理员定的，改不了）
2. 命令行临时参数
3. 项目里 `.claude/settings.local.json`（**私人设置，不提交 git**）
4. 项目里 `.claude/settings.json`（**团队共享设置，提交 git**）
5. 用户级 `~/.claude/settings.json`（个人所有项目的默认设置）

**最实际的三个用处**：

1. **少弹权限窗**：在 `permissions.allow` 写上允许的命令（如 `Bash(uv run python scripts/validate_localization.py)`），以后不再每次弹窗。本仓库 `.claude/settings.local.json` 已有 3 条允许规则。
2. **团队共享 vs 私人**：对整个项目成立的设置放 `.claude/settings.json` 提交 git，队友拉下来生效；只跟本机有关的放 `.claude/settings.local.json`（不提交）。
3. **hooks（钩子）**：如"每次提交前自动跑校验"这种自动化写在 settings.json——是程序行为，归设置管，不归记忆管。

**cleanupPeriodDays**：字面"清理周期天数"。Claude Code 本地攒的缓存——checkpoints（检查点存档）、后台任务记录（`~/.claude/tasks/`）、shell 环境快照（`~/.claude/shell-snapshots/`）、备份（`~/.claude/backups/`）——保留多少天、超了自动清，**默认 30 天**。不清记忆、不动项目文件，只清可再生成的缓存。硬盘紧张调小（如 7），想留更多存档点调大。

**边界**：settings 的具体 key 和 /config 行为**跟版本有关、可能变**；但"设置管程序行为、记忆管 AI 内容"是稳定原理。

### Q7：大融合——腾讯 L0-L3、Anthropic Dreaming，和 Claude Code 怎么对应？

**结论：那两篇文章讲的不是"另一种记忆"，而是同一套东西的理论版；Claude Code 里每个机制都能对号入座。融合不起来，是因为在找一个叫"记忆系统"的单一大厦，而实际它是一条分层流水线——不同成熟度的记忆，住在不同地方、由不同机制在不同时机加载。**

#### 腾讯 L0-L3 在 Claude Code 里分别住哪

| 腾讯分层 | 是什么 | Claude Code 里的对应物 | 谁来写 |
|---|---|---|---|
| **L0 原始对话** | 高保真、低密度的原始记录 | 电脑上 `~/.claude/projects/*.jsonl` 全部会话存档 + checkpoints | 系统自动存 |
| **L1 原子事实** | 一条条事实、决定、踩过的坑 | **auto memory 小卡片**（一文件一件事）+ **学习笔记** | AI 顺手记 / 你记 |
| **L2 场景记忆** | 围绕项目/场景组织的高密度规矩 | 项目 **CLAUDE.md**、`.claude/rules/`、各 skill 的 **SKILL.md** | 你和 AI 共同沉淀 |
| **L3 核心画像** | 稳定模式、长期画像、高层认知 | 全局 **`~/.claude/CLAUDE.md`**（你是谁、你怎么干活） | 你 |

流水线方向：**L0 → L1 → L2 → L3 一路提炼**，且腾讯强调"上层抽象和下层证据**都要保留**"——Claude Code 恰好如此：原始对话永远躺本地（L0 证据），提炼出的卡片和说明书在上面随取随用（L1-L3 抽象）。平时用高层记忆省阅读量，要核对细节时 `/resume` 翻回原始对话。

#### 腾讯"四类资产"对照

| 四类资产 | 回答什么问题 | Claude Code 对应 |
|---|---|---|
| Chat Memory（对话记忆） | 当时为什么这么定？试过哪些路？ | auto memory + 会话存档 + `/resume` |
| Wiki（项目知识） | 项目已经知道什么？规矩在哪？ | CLAUDE.md + `@导入` 文档 + 飞书知识库/本地 md |
| CodeGraph（代码结构） | 改这个会影响哪？ | **代码本身**——AI 用 grep/glob 现场读文件（Anthropic 说的"文件系统即记忆"，不另建图数据库） |
| Skill（验证过的工作流） | 这类事通常怎么做、怎么验收？ | **skills** 目录（SKILL.md + references + scripts） |

#### Anthropic 演讲的演进史 = 这几天学的东西

上下文工程一年演进四站，每站都学过：

1. **CLAUDE.md 阶段**："一个 markdown 文件，效果好得不讲道理"——但越长越臃肿 →
2. **memory tools 阶段**：让 AI 自己决定何时读写记忆（= auto memory）——带内整理有两个先天局限 →
3. **skills 阶段**：渐进式暴露，平时只看书名、用时才抽书（= skill frontmatter 机制）→
4. **文件系统式记忆（当前最佳实践）**：记忆就是一堆 markdown 文件，AI 用普通文件工具自己搜、自己管（= auto memory 的 MEMORY.md + 小文件，也 = 学习笔记仓库）。

#### Dreaming（做梦/离线整理）——融合的最后一块拼图

带内记忆（in-band，干活顺手记）两个**先天局限**：

1. **分心**：AI 一边干活一边想"这点要不要记给未来的自己"，两件事抢算力；
2. **视野受限**：每个 session 白纸开场，**看不到跨会话模式**——你为它反复犯同一个错生气，它不知道你在别的会话已生过三天气。

**Dreaming**：夜里派一个"校长"角色，不干活、专门翻遍所有班级作业（所有会话记录），找出"全班都在同一道题栽跟头"这类跨会话模式，**提议修改记忆库**，人审批。类比学校里老师批改作业、校长巡课改教案。

**Claude Code 目前没有内置 Dreaming。但我们已经在做人肉版**：

- 每天写**学习日报**（今天学了啥、卡在哪、关键收获）= 校长翻当天所有班级作业；
- 把飞书文章整理成**学习笔记**、再沉淀成仓库里的**教程文档和 skills** = 跨会话模式提炼成 L2/L3 资产；
- `/submit-notes` 流程 = 提炼完归档入库。

腾讯那句"**任何错误只犯一次**"，在个人这儿的版本：踩一个坑 → 写进日报/笔记 → 反复出现就升级成 CLAUDE.md 规矩或 skill → 以后 AI 开工就带着。

想自动化也行：Dreaming 本质是"会话外跑一个整理任务"，可用 `/loop`（定时循环跑提示词）或定时派 subagent，定期翻记忆目录和最近会话、提议增删改、人审批。**但现阶段建议继续用人肉版**——还在建体感，自动整理会绕过去自己的提炼能力。

#### 为什么一直"融合不起来"

因为在找一个**地方**放所有记忆，答案是一条**流水线 + 分工表**：

> **原始素材（L0）躺在本地和飞书 → 定期复盘（Dreaming，写日报）→ 提炼成原子卡片（L1，auto memory/学习笔记）→ 稳定下来成项目规矩（L2，CLAUDE.md/skills）→ 跨项目的心法成个人风格（L3，全局 CLAUDE.md）。**

每层东西**放对地方、在对的时机被加载**就够了，不需要合并成一个文件。腾讯那句"**完整属于资产池，相关属于当前任务**"——飞书收藏、学习笔记仓库就是资产池；CLAUDE.md 和 MEMORY.md 索引就是"当前任务只装配相关部分"的装配口。

**晋升路径**（以后遇到任何信息按这个判断放哪）：

> 踩了个坑 → 先让 AI 记进 auto memory（L1）→ 发现反复踩/对项目成立 → 写进项目 CLAUDE.md（L2）→ 发现是一套固定流程 → 封装成 skill（Skill 资产）→ 发现是跨项目通用心法 → 写进全局 CLAUDE.md（L3）。

## 常见误区（补充三个没问到但马上会踩的点）

**1. 以为"原始资料"02-memory 里没有。** 错。Claude Code 把**每次对话的完整记录**都存在 `~/.claude/projects/` 下的 jsonl 文件里（L0）。飞书 26 篇收藏是外部 L0，本地会话是内部 L0。想找"上次怎么解决的"，`/resume` 翻旧会话就是查 L0。

**2. 到处找记忆治理工具，忘了 git 就是免费的治理系统。** 两篇文章都讲生产级记忆需要"版本、权限、回滚、评审"——不用自己造：**项目 CLAUDE.md / settings.json 提交 git**，就有版本历史、能回滚、团队共享、改动可见（评审）；**CLAUDE.local.md / settings.local.json 不提交**，就是私人草稿层。`.gitignore` 里就该躺着 local 文件名。这一条直接配齐两篇文章的"护栏四件套"（版本、并发、权限、可移植性）。

**3. "想到了就往里加"最大的风险是只加不删。** 记忆会过时、会记错——腾讯 22,361 条经验关系里，最后只敢保留 **231 条**作为"强资产"，其余 2 万多条降级为"仅参考"。直接含义：① MEMORY.md 索引超 200 行后面不生效，**定期清理比往里堆重要**；② 一条记忆被证明错了或过时，删掉/改掉，别让它持续误导以后每个会话；③ CLAUDE.md 保持短（≤200 行），长材料放笔记/skills 用时再调——这就是"渐进式暴露"的落地。

## 操作步骤（实际怎么用这套体系）

1. **开工时**（自动发生，不用敲命令）：Claude 自动拼上 托管层 → 全局 CLAUDE.md → 项目 CLAUDE.md → 目录 CLAUDE.md → CLAUDE.local.md，并加载本项目 MEMORY.md 索引。
2. **干活中**：发现长期事实/踩坑，直接说"记住：……"，或手动写 memory 小卡片；想确认它记了什么，用 `/memory` 查看。
3. **下班后**：写学习日报（Dreaming 人肉版）：今天学了啥、卡在哪、什么经验值得沉淀。
4. **沉淀晋升**：日报里反复出现的坑 → 升级进项目 CLAUDE.md；固定流程 → 封装成 skill；跨项目心法 → 全局 CLAUDE.md。
5. **定期清理**：翻 MEMORY.md 和 CLAUDE.md，删过时、改错记错；local 文件确认在 `.gitignore` 里。
6. **权限烦了**：不是改记忆，是改 `.claude/settings.local.json` 的 `permissions.allow`（或用 `/config` 界面勾）。
7. **想接昨天的活**：`claude -c`；想翻旧会话：`/resume`；走错路：连按两次 Esc 开 checkpoint 回退。

## 具体示例（落在本仓库）

- 本仓库根目录 `CLAUDE.md` = **L2 项目记忆**：写着"兼容性优先、frontmatter key 不许翻译、提交前跑 validate_localization.py"。
- `~/.claude/CLAUDE.md`（个人）= **L3**：该写"用中文、先讲用途再讲命令、我做焊接工厂+外贸"这类跨项目偏好。
- 本仓库 `.claude/settings.local.json` = **设置（不是记忆）**：已有 3 条 permissions.allow，让常用命令不弹窗。
- `学习笔记/` 整个目录 = **L1 资产池 + Dreaming 产物**：日报是原始复盘，正式笔记是提炼后的原子知识，C-Skills-Practice 里封装出的 skill 是晋升到"Skill 资产"的最终形态。
- 飞书「内容索引」多维表格 26 篇收藏 = **外部 L0/L1 素材库**，靠日报和笔记逐步提炼进 L2/L3。

## 选择方法（一张表决定"这条信息放哪"）

| 这条信息…… | 放哪里 | 层级 |
|---|---|---|
| 只对这台电脑/我本人在这个项目成立 | `CLAUDE.local.md` / `settings.local.json` | 本地层 |
| 是一个刚踩的坑、一次性事实 | 让 AI 记 auto memory | L1 |
| 对这个项目长期成立的规矩 | 项目 `CLAUDE.md`（提交 git） | L2 |
| 只在某个子目录干活时才适用 | 子目录 `CLAUDE.md` | L2 |
| 一套反复执行的固定流程 | 封装成 skill | Skill 资产 |
| 我这个人跨所有项目的习惯/身份 | `~/.claude/CLAUDE.md` | L3 |
| 长资料、原文、素材 | 学习笔记 / 飞书知识库，用时 `@导入` | L0/L1 资产池 |
| 权限、hooks、模型、缓存天数 | settings.json（**不是记忆**） | 设置 |

## 最短速查（复习只看这段）

- **四个"是什么"**：CLAUDE.md = 岗位说明书；settings.json = App 设置面板（不是记忆！）；auto memory = AI 自己记的工作卡片（MEMORY.md 索引 + 一文件一事，前 200 行/25KB 上限）；session = 一个班次。
- **加载顺序**：托管 → 用户（`~/.claude/CLAUDE.md`）→ 项目（`CLAUDE.md`）→ 目录 → local（`CLAUDE.local.md`），**拼接不覆盖**，越具体越靠后。
- **L0-L3 映射**：jsonl 会话存档 = L0；auto memory + 学习笔记 = L1；项目 CLAUDE.md + rules + SKILL.md = L2；全局 CLAUDE.md = L3。
- **四类资产映射**：Chat Memory = auto memory/会话；Wiki = CLAUDE.md + @导入 + 飞书；CodeGraph = 代码本身（grep/glob）；Skill = skills 目录。
- **Dreaming**：Claude Code 没内置；写日报 + 整理笔记 + `/submit-notes` 就是人肉版；自动化靠 `/loop` 或定时 subagent（现阶段不建议）。
- **晋升路径**：踩坑 → auto memory → 项目 CLAUDE.md → skill → 全局 CLAUDE.md。
- **设置优先级**：managed → CLI 参数 → settings.local.json（私人）→ 项目 settings.json（共享）→ 用户 settings.json。
- **cleanupPeriodDays**：本地缓存（checkpoints/tasks/shell 快照/备份）保留天数，默认 30，不动记忆和项目文件。
- **治理靠 git**：项目级文件提交（版本/回滚/评审），local 文件 gitignore。
- **一句话心智模型**：记忆不是一个文件，是一条"原始对话 → 卡片 → 规矩 → 个人风格"的提炼流水线；完整属于资产池，相关属于当前任务。
