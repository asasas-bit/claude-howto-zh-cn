## 💡 关键收获（选 1-3 个最有价值的知识点，多写一点）

### 未 push 的 commit 就是"草稿"，可以随便重写
今天最大的解放感是搞清楚了 git 的分层：**push 之前**的 commit 全部属于本地历史，`amend`、`rebase -i` 想怎么改就怎么改；**push 之后**才需要谨慎。所以下次再看到 `Your branch is ahead of 'origin/...' by N commits`，不要把它当"已经定型的历史"看，它其实是"还能返厂重修的草稿"。今天把只有 3 个案例的旧 commit 直接换成"10 个案例一次登场"的新 commit，就是这个逻辑落地——旧 SHA `cd7a92d` 从来没进过远端，改掉它零风险。

### 命名一致性是"未来自动化"的地基
今天顺手把 01/02/03 里的 `可直接使用的提示词.md` 统一改成了 `创建该Skill的AI提示词.md`，让 10 个案例的三件套（提示词 + 案例说明 + 测试用例）文件名完全对齐。这不是强迫症——如果以后想写个 script 批量扫描"每个案例的提示词内容"，命名不统一就得写一堆 `if-else`。**趁改动还没 push、量还小的时候统一命名，比日后写补丁便宜得多。**

### Slash command 本身就是"学习复盘"的载体
今天让我惊讶的一点：自己写的 `/git-safe-submit` 竟然真的在自己犯浑（边生成边提交）时救了自己。它强制我"先看预览再确认"，逼我意识到当前状态不干净——如果直接手敲 `git commit`，我可能就把 04-10 也塞进那个"3 个案例的旧 commit"里搞得更乱了。这印证了那两篇元层笔记的核心观点：**Skill 不是给别人写的，是给未来那个手忙脚乱的自己写的。**
